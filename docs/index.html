Render BlameProject record · built 2026-11-16 from main

Render Blame

Render Blame is a Blender add-on that tells you why a Cycles render is slow: which objects and materials take the most render time, both as a share of the frame and as cost per pixel against the average, with a heatmap. It is for anyone who renders in Cycles. Luqman asked on 2026-11-16 for "a Blender add-on that's useful and nobody has made"; a market search found per-object shading cost was the clearest gap (see 01-idea). Third Blender add-on after Pipeline and Retopo Kit; released free.

Why this project exists

Blender reports how long a frame took, never what made it slow. People find out by hiding objects one at a time. Existing add-ons estimate total time or time modifiers (Render Profiler, Modifier Profiler); none splits Cycles shading time by object.

What counts as "done"

v0.1: one button gives a correct ranking on real scenes, volumes included, without touching the user's file. Release: public repo, release zip, extensions.blender.org listing.

What is NOT in scope

EEVEE (no Render Time pass); fixing the scene for the user; per-frame animation profiling (later maybe).

How it gets made · 08-record.md

Pipeline

One button, one background Blender, one report. The user's file is copied, never changed.

  1. 1. CopyThe open file is saved as a copy to a temp folder (relative paths remapped)`__init__.py` · `RB_OT_run`
  2. 2. Probe renderA background Blender renders the copy on the CPU at 25% size, ≤64 samples, with the Render Time pass and Cryptomatte object + material`probe.py` · `setup()`
  3. 3. Split the timeEvery pixel's time is shared among the objects/materials covering it, by Cryptomatte coverage; what's left is the world`analyze.py` · `attribute()`
  4. 4. VolumesEach volume is hidden and the frame rendered again; the time that disappears is its cost`probe.py` · `main()`
  5. 5. ReportShare of time, cost per pixel (×average), hints, heatmap PNG → panel`analyze.py` · `heatmap()`, `__init__.py` · `_poll_job()`

Tools

Cycles Render Time passPer-pixel render time — CPU only, which is why the probe runs on the CPU
CryptomatteWhich object / material covers each pixel, and how much
OpenImageIO + numpyRead the multi-part EXR and do the maths (both ship with Blender)
tests/run_tests.sh12 end-to-end checks in headless Blender

01-idea.md · 2 sections

The idea

Problem: a Cycles frame takes minutes and nobody can say which object or material is responsible.

Idea: Cycles writes a per-pixel Render Time pass. Combine it with Cryptomatte's object/material coverage and you can split the frame's time among everything in it. Rank by cost per pixel (×average), because share of time mostly follows screen area.

Market search, 2026-11-16 (why this one)

Superhive is crowded in 2026. Already taken: scene/asset validators (Shipshape, Asset Preflight, InspectOps), modifier profilers (Modifier Profiler, Render Profiler, Profiling Buddy), .blend diff (Versionproof), file-size analysers (File Size Inspector, BlockBuster), whole-scene render-time estimators, interactive tutorials, four Godot pipelines. Nothing ranks Cycles shading cost per object — confirmed by two searches.

Alternatives weighed

  • Hotkey Coach — watches menu clicks and teaches the matching shortcut (only a hotkey press tracker exists). Kept as the next add-on; risk: Blender doesn't say whether an operator came from a key or a menu.
  • Door-height scale checker — too close to Shipshape Validator. Dropped.

02-planning.md · 2 sections

Planning

v0.1.0 (built 2026-11-16)

  • Button Find What's Slow (3D Viewport sidebar tab "Render Blame"; also Properties ▸ Render, collapsed).
  • Saves a copy of the file to temp; a background Blender (--factory-startup) runs probe.py: CPU, probe size 25%, samples capped at 64, denoise/compositor off, Render Time pass + CryptoObject + CryptoMaterial (depth 6), multilayer EXR, 32-bit.
  • analyze.py splits cost per pixel by Cryptomatte coverage; leftover = world/background.
  • Volumes (no IDs) measured by leave-one-out: hide, re-render, time that vanished (up to 6).
  • Results: Objects/Materials toggle, sort by share or cost per pixel, red when ≥1.5× or a volume, material hints (glass, subsurface, coat, hair, transparency, volume), click to select (a material selects every object using it), heatmap image (packed into the file).

Next (ideas, not committed)

  • Try on Luqman's real scenes; tune the 1.5× threshold.
  • Release: public GitHub repo, release zip, extensions.blender.org.
  • Maybe: light cost (leave-one-out per light), animation frames, world/HDRI cost.

04-methods.md · 0 sections

Methods

  • Tests: ./tests/run_tests.sh (builds tests/scene.blend if missing, then 12 end-to-end checks in headless Blender; timers don't tick headless, so the test calls _poll_job() by hand).
  • Build: blender --command extension build --source-dir render_blame --output-dir dist; validate with --command extension validate render_blame.
  • Blender 5.x multilayer EXR: set image_settings.media_type = "MULTI_LAYER_IMAGE" (file_format then is only OPEN_EXR_MULTILAYER). Each pass is its own EXR part: read with seek_subimage in a loop.
  • Cryptomatte manifest hash → stored float: flip bit 23 when the exponent is 0 or 255.
  • GUI screenshot without a human: run Blender with a --python script that uses bpy.app.timers then bpy.ops.screen.screenshot; add a quit timer as a safety net. Scripts cannot set Region.active_panel_category (read-only).

06-decisions.md · 0 sections

Decisions

  • D-001 (2026-11-16) Probe always on CPU. Cycles writes the Render Time pass only on the CPU (on Metal the pass is missing; GPU "Debug Sample Count" ranked the glass ball cheapest, so it is not a usable stand-in). Relative cost per object is what matters.
  • D-002 Run in a background Blender on a saved copy, not in the user's session: the UI stays free and nothing has to be restored.
  • D-003 Cryptomatte over Object Index pass: coverage weights share edge pixels fairly and give materials too.
  • D-004 Volumes by leave-one-out: they write neither object index nor Cryptomatte (checked).
  • D-005 Rank by cost per pixel as well as share: share mostly follows screen area (the floor took 49% at 1.0×).
  • D-006 Main panel in the 3D Viewport sidebar: the Render properties panel sat collapsed at the bottom of a long tab on first open.
  • D-007 Free, GPL-3.0 — Luqman's choice, 2026-11-16.
